# Markdown 文档排版整理设计

## 目标

统一整理仓库现有 Markdown 文档，使其在 GitHub 和 Obsidian 中均能稳定、清晰地渲染，重点解决普通单换行在 GitHub 中被折叠为空格的问题。

## 范围

- 整理 `README.md`。
- 整理 `conversation/PersonaMem-v3.md`。
- 不修改研究内容、措辞、错别字、标点或中英文表达。
- 不增删正文，不调整内容顺序。

## 排版规则

- 使用空行划分独立段落，不批量插入 `<br>`。
- 在标题前后保留空行，但不改变标题文字和层级。
- 为已有 Markdown 有序列表补充序号后的空格。
- 规范列表、表格、引用和代码块周围的空行。
- 保留 YAML front matter、URL、表格单元格、代码块及代码内容。
- 删除无语义的行尾空白；不依赖行尾双空格实现换行。
- 对无法明确判断语义的连续文本采取保守处理，不重组或改写句子。

## 验证

- 检查 Markdown 标题、列表、表格和代码围栏结构。
- 检查差异，确认没有原文字符被改写或删除。
- 检查所有现有 Markdown 文件均已纳入整理范围。
- 确认工作区中不存在非预期文件改动。
